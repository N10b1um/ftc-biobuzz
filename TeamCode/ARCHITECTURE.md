# Архитектура TeamCode

Основа — [wydentis/ftc-decode](https://github.com/wydentis/ftc-decode/tree/46db77ca83fc1ec1182087df25ff1ff58ccd1e45/Team28420/src/main/java/org/firstinspires/ftc/team28420), commit `46db77ca83fc1ec1182087df25ff1ff58ccd1e45`.

В старом проекте `BlueTeleop` обрабатывает геймпад и вызывает фасад `handlers.Actions`. Фасад создаёт модули, выполняет `setup/update/log` и координирует их работу. Аппаратные классы находятся в `module`, значения команд — в `types`. `RobotController` управляет ручным bulk caching REV. Обработчики камеры и сортировки нужны только для соответствующих механизмов.

В этом проекте сохранены эти границы ответственности и единый фасад. Код написан на Kotlin. Рабочие механизмы — движение и интейк; стрельба, хранилище, vision, автономка, наведение и их конфиги удалены. Нет планировщика action-сценариев и выключенных заготовок будущих механизмов.

| Слой | Ответственность |
| --- | --- |
| `opmodes/teleop/MainTeleOp` | `initialize`, `move`, `manualMove`, геймпад, жизненный цикл |
| `handlers/Actions` | Фасад двух модулей, общая телеметрия, остановка |
| `module/Movement` | Четыре мотора, смешивание команд, компенсация напряжения |
| `module/Dribbler` | Мотор интейка, кэш датчиков, неблокирующее устранение заклинивания |
| `module/RobotController` | Ручной bulk caching и восстановление предыдущего режима |
| `module/PinpointHeading` | Внутренний источник курса движения относительно поля |
| `types` | Неизменяемые команды движения и мощности колёс |
| `config` | Параметры FTC Dashboard |

## Отличия от прошлого сезона

Аппаратные настройки и алгоритмы взяты из текущей рабочей папки: `RUN_WITHOUT_ENCODER`, торможение, коэффициент бокового движения, геометрия базы, компенсация напряжения и anti-jam. Прошлогодние скорости энкодеров не перенесены: они относятся к другому роботу. Полярный изменяемый вектор заменён неизменяемой командой `MovementParams(forward, strafe, turn)`; отдельный `PolarVector` этой версии не нужен.

Сохранено текущее преобразование курса: forward — вперёд, strafe — вправо, turn — по часовой стрелке; курс Pinpoint — против часовой стрелки в радианах. При курсе +90° команда вперёд по полю превращается в движение вправо относительно робота. Позиционное управление и автономная локализация удалены; Pinpoint используется только для курса. При отключённом Pinpoint доступно движение относительно робота.

Сначала `Actions.update()` очищает bulk cache и читает курс, затем TeleOp выдаёт команды движения и интейка. После команды интейка фасад один раз вызывает его `update()`, чтобы датчики и выход мотора обрабатывались в том же цикле. Это устраняет задержку команд на один цикл. Отпускание триггера и команда остановки сразу обнуляют мотор, включая фазу anti-jam. При выключении anti-jam сбрасывается накопленное время заклинивания. Завершение, отмена до старта и исключение проходят через `finally`; остановка остальных моторов выполняется даже при ошибке одного из них.

## Управление Main TeleOp

| Управление gamepad1 | Действие |
| --- | --- |
| Левый стик | Вперёд/назад и боковое движение |
| Правый стик X | Поворот |
| Нажатие левого стика | Торможение шасси |
| Левый триггер | Интейк с пропорциональной мощностью |
| Левый триггер + левый бампер | Выброс с `EJECT_POWER` |
| Circle / B | Остановка интейка, приоритет над триггером |
| Back / Share | Переключение системы координат по фронту нажатия |
| Options / Start | Сброс курса Pinpoint по фронту нажатия |

Левый триггер и левый бампер, кубический отклик стиков, deadzone и кнопка торможения соответствуют структуре прошлогоднего TeleOp. Пропорциональная мощность интейка сохранена из текущего сезона; значение триггера умножается на `INTAKE_POWER`, ограниченную диапазоном 0…1. Переключение системы координат и сброс курса также сохранены из текущего сезона.

`Intake Diagnostics & Tuning` использует тот же `Dribbler`: правый триггер запускает интейк, левый — выброс с настроенной мощностью; A сбрасывает пиковый ток. Anti-jam действует и здесь; для измерения поведения без него выключите `ENABLE_ANTI_JAM`.

## Настройка

Все поля настройки публикуются через `@Config` и `@JvmField`.

| Конфиг | Когда применяются изменения |
| --- | --- |
| `ModuleConfig` | При создании OpMode: отключённое оборудование не запрашивается |
| `DriveConfig`: имена, Pinpoint | При создании/setup; перезапустить OpMode |
| `DriveConfig`: инверсии моторов | Перед каждой командой движения; при изменении моторы сначала останавливаются |
| `DriveConfig`: геометрия, боковой коэффициент, напряжение | Каждый цикл |
| `IntakeConfig`: имя, инверсия | При создании/setup; перезапустить OpMode |
| `IntakeConfig`: мощность, anti-jam, пороги, интервалы | Каждый цикл; мощность = триггер × INTAKE_POWER |
| `TeleOpConfig` | Каждый цикл, кроме начальной системы координат |

Размеры и смещения задаются в миллиметрах, ток — в амперах, скорость — в тиках/с, времена — в секундах, кроме `CURRENT_POLL_INTERVAL_MS`. Компенсация не применяется при отсутствующем или слишком низком напряжении. Нечисловая команда или недопустимая геометрия дают нулевую мощность; насыщенные команды нормализуются с сохранением пропорций.

## Проверка

Тесты находятся в `src/test/java/org/firstinspires/ftc/teamcode`, повторяют пакеты production-кода и используют реальные модули с подставными интерфейсами FTC-моторов и управляемыми часами. Они не требуют Control Hub. Статические настройки восстанавливаются после каждого теста.

```sh
JAVA_HOME=/usr/lib/jvm/bellsoft-java17.x86_64 ./gradlew :TeamCode:testDebugUnitTest :FtcRobotController:assembleDebug --offline --no-daemon
```

На другой машине укажите свой JDK 17; `--offline` требует заранее загруженных зависимостей. JVM-тесты проверяют команды и переходы состояний. Направления физического вращения, качество курса Pinpoint и пороги заклинивания после рефакторинга нужно подтвердить на роботе.

## Согласование движения с наблюдениями на роботе

Сообщённое поведение Robot Centric: стик вперёд поворачивает против часовой стрелки, боковой стик вправо двигает влево, правый стик вправо двигает назад. Для стандартного X-mecanum эти три наблюдения согласуются с переставленными передним и задним правыми моторами и обратным направлением левой стороны относительно прежних настроек.

После этих наблюдений правые моторы переставлены проводами на хабе. В коде дополнительного обмена нет: переднее правое колесо — `rightFront`, заднее правое — `rightBack`. Левые моторы используют `FORWARD`, правые — `REVERSE`. Одна внешняя зубчатая пара на каждом колесе уже учтена в этих направлениях; дополнительный общий минус к мощности не добавляется.

Исходная ошибка сопоставления выведена из движения, а не подтверждена отдельным запуском каждого колеса; перестановка проводов сообщена пользователем. `MovementWiringTest` моделирует одну внешнюю зубчатую пару, зеркальное крепление моторов и стандартные X-колёса: прежние настройки воспроизводят все три описанные ошибки, исправленные разделяют продольное движение, боковое движение и поворот. Сначала проверьте три отдельные команды в Robot Centric. После физической перестановки проводов и загрузки новой версии перезапустите OpMode; инверсии теперь применяются при следующей команде движения без перезапуска.
